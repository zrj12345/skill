# 审查补正：真实界面截图的端到端流水线

适用驳回意见：要求补充软件运行**全部功能**对应的界面截图 + 连贯操作说明，
且截图真实、完整、清晰，与申请表的软件主要功能/技术特点/源程序量相符合。

## 0. 目录约定（回退链路完整）

```
项目/
├── XXX_补正材料/              # 原始未脱敏截图 + 各类备份 docx
├── XXX_补正材料_脱敏原图/     # 只打码、无标注
├── XXX_补正材料_标注版/       # 脱敏 + 手写标注 PNG + 预览 PDF
└── XXX/设计原理.docx          # 提交件
```
每轮改动前先把旧版 PNG/docx 复制成 `_打码前_*` / `设计原理_*备份.docx`。

## 1. 截图阶段

- **浏览器**：`agent-browser` daemon 若反复挂起，直接用 Python Playwright +
  系统 Chrome：`pw.chromium.launch(headless=True, executable_path=r'C:\Program Files\Google\Chrome\Application\chrome.exe')`。
  本机 ms-playwright 缓存版本常与新装 playwright 期望版本不符，指定系统 Chrome 免下载。
- **登录**：从源码找初始账号（如 `migration.go` 的 `userInit()`）；
  `GET /api/v1/code` 取 uuid + base64 验证码 → 图片存盘 → 用 ViewImage 读码 → `POST /signin`。
- **登录态注入**：Vue + pinia-persistedstate 的 localStorage key 通常是 store id（如 `user`）。
  必须注入完整 `{token, userInfo}`，其中 `userInfo` 要带 `/info` 返回的 **menus**，
  否则左侧导航不渲染。`/info` 只带 `X-Tkn`，多余 header 可能 502。
- **页面清单**：从 `/info` 菜单树或前端 JS bundle 的路由表提取，逐页 1600×1000 全页截图。
  再补关键操作子页：新增/编辑弹窗、权限树、文件上传、日志过滤结果。
- **别漏登录页**：它不在菜单里，单独用无登录态的上下文截。

## 2. 脱敏阶段（最容易漏，务必逐页目检）

**顺序：原图 → 马赛克 → 手写标注。**

必查清单（曾用脚本扫描定位，仍必须肉眼看一遍全图）：
1. 顶栏右上角当前登录账号（几乎每张页面都有）；
2. 用户列表的登录账号 + 真实中文姓名 —— **新增用户弹窗的背景列表同样要打**；
3. 日志页的用户名列 + 客户端 IP 列；
4. 登录页图形验证码明文；
5. **服务端地址 / URL / IP:端口 / 主机地址**（本案转码配置页的
   `http://207.121.108.68:9927` 就是自动扫描漏掉的，用户复核时才指出）。

实现参数：
- 像素化：区域缩到 `w//9,h//9`（BILINEAR）→ NEAREST 放大贴回，块约 9~10px。
- 表格文字用深色像素行扫描（列内逐行统计灰度 <150 的像素，连续段 5~46px）。
- **弹窗遮罩使背景变暗，扫描会整段误判** → 这类页用固定行框，且框元组恒为 `(x0,y0,x1,y1)`。
- **细笔画文字（URL/IP）像素化后对比太淡，像涂抹不像马赛克** → 像素化后再做
  `v' = 255 - (255-v)*2.2`，灰白方格才清晰、与头像打码风格一致。
- 框选不要压到红色手写标注：先确定标注定落点，或避开红字/箭头所在行列。

## 3. 标注阶段

- 红色实心圆（略不规则）写白色数字 `1 2 3 4`，**用文字数字，不用圈码字符**。
- 短箭头：多段折线 + 随机抖动，指向控件，别画成长直线。
- 楷体 `simkai.ttf` 红字短句，6~10 字，直接写在步骤旁边；**不要【】方括号**，
  改成自然说法（「点搜索」「填配置项与值」）。完整连贯说明留在正文。
- 落点自动选空白：8 方向随机 + 背景干净度评分 + 重叠惩罚；顶部按钮区禁止向上；
  弹窗页优先写在四周灰遮罩。
- 不扩展画布 → docx 的 `<wp:extent>` / `<a:ext>` 不用改，页数不变。
- 控件坐标可用蓝 `#409EFF` / 红 `#F56C6C` 连通域检测提取，不必手工估。

## 4. 替换进 docx

1. 用 **md5 精确映射**建立 `word/media/imageN.png` ↔ 原始 PNG，
   基准固定为「替换前备份.docx」，可重复执行、可回退。
2. 只换 ZIP 内对应 media 字节，其他 part 原样保留 → 章节/表格/图注/正文/版式全不变。
3. 尺寸必须与原件一致；不一致要同步改每个 `<w:drawing>` 里的 `<wp:extent>` 和 `<a:ext>`。
4. 匹配数不等于预期张数时**立即停止**，防止误改其它图片。
5. WPS 占用文档时 `os.replace` / `shutil.move` 报 WinError 5，
   但 `open(path,'wb')` 直接覆写通常可行。

## 5. PDF 同步与页数

- 首选 `Kwps.Application`（不是 `Word.Application`，后者被 WPS 接管会无限挂起），
  `Documents.Open(..., ReadOnly=True)` + `ExportAsFixedFormat(pdf,17)`，
  `ComputeStatistics(2)` 读真实页数。外层加硬超时。
- 若 PowerShell COM 被安全策略拦截、或 pywin32/comtypes 未安装：
  改用 PyMuPDF `Page.replace_image(xref, filename=...)` 直接替换 PDF 内嵌图，
  页数不变。定位 xref 用「尺寸 + 缩略图 MAE 最小」；
  替换后用 `page.get_image_info(xrefs=True)` 确认页面实际引用的是新对象。
- WPS 打开文档会写入作者 `admin`，**导出后必须再清一次文档属性**。

## 7. 用户沟通要点

- 用户给的示例图是风格基准，先确认「能否在图片中标注」再动手。
- 文字说明写在步骤旁边，编号用文字 `1 2 3 4`，不要规整、要像真人做的。
- 用户复核指出漏打码时，只处理指出的那一处，不要顺手改掉其它已确认内容；
  重新生成时从「打码前备份」出发，避免二次马赛克。
