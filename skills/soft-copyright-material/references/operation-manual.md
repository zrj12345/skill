# 操作说明（界面截图 + 操作步骤）

> **来源：CMS 软著最终过审范式（必须照做）。** 演进过程：
> ①最初只交设计原理说明书 → 被要求「配合文字介绍软件相关操作」；
> ②补正截图、每张配 2~4 句说明 → 仍被打回「功能操作介绍需连贯、全面」；
> ③后来单独出一份《系统操作说明书》Word → 用户指出**这也不对**；
> ④**正确做法（CMS 最终过审）**：把操作说明**嵌入设计原理说明书第二章「系统功能模块
> 设计」的各个功能模块小节**，截图带**红色手写箭头标注 + 敏感信息马赛克**，且
> **截图紧扣本软著主题**。本文件即描述④。

## 0. 铁律（三条，违反任一条用户都会退回）

1. **嵌入设计原理说明书第二章，不单独成册**。操作说明是第二章各功能模块小节的一部分，
   不是另一份 Word。只有用户在当前这轮**明确**说「单独出一份操作说明书/用户手册」时
   才另立 Word，且即便如此也优先反问确认。
2. **截图必须「脱敏马赛克 + 红色手写箭头标注」双处理**。顺序恒为：原图 → 马赛克 →
   手写标注。只打码不标注 = 不合格；标注盖在马赛克上被糊掉 = 不合格。
3. **截图紧扣本软著主题**。只放与申请表中「软件主要功能」直接相关的界面；
   其他软著主题的功能页（如给"数据采集与网关管理"配统计大屏、用户/菜单/权限、
   设备仿真）一律不放，宁缺毋滥。软件全称叫什么，截图就证明什么。

## 1. 什么时候必须做

- 用户说「要有操作说明 / 操作介绍 / 用户手册 / 使用说明」；
- 审查意见提到「配合文字介绍软件相关操作」「功能操作介绍需连贯、全面」「截图需真实、
  完整、清晰，与申请表主要功能相符合」。

两种情形都按本文把操作说明嵌入设计原理说明书第二章。

## 2. 文档落点：设计原理说明书第二章

CMS 最终版的结构（照抄这个组织方式）：

```
第二章 系统功能模块设计
  2.1 功能模块总览          -> 表 + 图 3-2 功能模块分解图（原有，保留）
      图 2-1 系统登录界面    <- 引导段 + 图 + 图注 + 操作说明段
      图 2-2 仪表盘主界面    <- 同上
  2.2 <功能模块一>           -> 原有功能说明表保留，随后：
      一句操作链路引导语（「X 是本模块核心对象，操作链路为『A → B → C』。」）
      图 2-3 <界面名>        <- 图 + 图注（居中加粗）+ 2~4 句连贯操作说明
      图 2-4 <界面名>
      ...
  2.3 <功能模块二>           -> 同上
  ...（每个功能模块小节都配 1~N 张紧扣该模块功能的界面截图）
第三章 核心模块设计说明      -> 保持不变（流程图、接口、数据结构）
```

- 图注编号用「图 2-1 … 图 2-N」，按第二章连续编号，**不与流程图图号体系冲突**
  （流程图是图 3-x 图 4-x 图 附-x，别去改）。
- 每张图**前**可有一句引导语串起操作链路；每张图**后**必须有 2~4 句**连贯动词句**
  操作说明，能对应到截图里被箭头标注的控件。
- 每张截图都要配说明，不允许出现「只有图没有操作文字」的裸图。

## 3. 操作步骤写法（连贯，不是罗列）

- **连贯动词句**：按操作先后写成「点击…→ 填写…→ 选择…→ 保存后…」，串成一段；
  每条都能对应截图里某个被箭头指到的控件。**不要**写成功能点清单。
- 引导语模板：「X 是本系统的核心管理对象，其操作链路为『列表查询 → 新增/编辑 →
  关联配置 → 保存生效』。」
- 说明段模板：「在左侧菜单点击『网关管理』进入列表（图 2-3）。顶部可按网关编号、
  在线状态组合筛选，点击『搜索』定位目标网关；列表展示网关编号、型号、在线状态与
  最近上报时间（图 2-3 标注 1~2）。点击『新增』弹出接入表单（图 2-4），填写网关编号、
  选择型号与采集协议后保存，网关即以离线状态登记入系统，等待首次上报后转为在线。」
- 正文中**不要**写真实账号密码 / 服务端 IP / URL，账号统一写「系统管理员账号」。
- 技术特点（统一鉴权 / RBAC / 归一化 / 时序入库等）要在对应模块的操作说明里自然带出，
  呼应审查意见「与申请表技术特点相符合」。

## 4. 截图处理流水线（原图 → 马赛克 → 箭头标注 → 嵌入）

### 4.1 取材：紧扣主题
从申请表「软件主要功能」逐条映射界面：软件叫什么，就截什么功能的页面。
例：「数据采集与网关管理」→ 网关管理/新增/详情/型号、驱动协议/协议库、采集模板分类、
设备实时数据、告警事件；**不要**放统计中心、用户/菜单/权限、设备仿真等跑题页面。

### 4.2 登录进系统
Vue SPA 用 Python Playwright + 系统 Chrome（见 SKILL 6.5 节），注入登录态后按菜单路由
逐页 1600×1000 截 `full_page=True`；关键操作再补弹窗子页（新增/编辑/权限树）。

### 4.3 马赛克（先做）
用 `scripts/desensitize.py --src 原始 --dst 脱敏原图 --extra boxes.json`。
新项目用 `--no-defaults --extra boxes.json` 只用自定义框；内置规则是 CMS 示例。
必打五类：顶栏账号、用户列表账号/姓名、日志用户列与 IP、验证码、服务端地址/URL/IP:端口。
弹窗遮罩背景里的账号同样要打。**逐张肉眼复核**，别只信脚本。

### 4.4 红色手写箭头标注（后做）
用 `scripts/handmark_reference.py` 的绘制原语（数字圆 `hand_circle` + 手绘箭头
`hand_arrow` + 楷体红字 `text_sticker` + 自动选空白落点 `choose_spot`）。
新项目须重写该文件顶部的 `SRC / DST / MARKS / SHORT`：
- `MARKS` 每项 = `(序号, 控件相对坐标(0~1), 完整说明, 落点)`，控件坐标用 Playwright
  量 `getBoundingClientRect()` 或按截图目测；
- `SHORT` 是图上短句（6~10 字，不要【】方括号），完整说明留在正文；
- 风格：红色实心圆+白数字、抖动箭头、楷体红字略倾斜；不扩展画布（尺寸不变→docx
  的 `<wp:extent>` 不用改、页数不变）；随机种子按「文件名+序号」固定，可反复微调。
- 脚本内部会先调用 `desensitize()` 再叠加批注，保证标注在最上层。

### 4.5 嵌入设计原理第二章
用 python-docx：定位第二章各功能模块小节的段落，`anchor._p.addprevious(new_p._p)`
把「引导段 + 图片 + 图注 + 说明段」插到小节内容之后、下一小节标题之前。
锚点用 `startswith` 且取最后一次出现（目录里也有章节名，取第一个会插错到目录）。
图片 `run.add_picture(标注图, width=Cm(15.5))`；正文首行缩进 21pt、宋体 10.5pt；
图注居中加粗 9.5pt。

### 4.6 若已嵌入、要替换图片（md5 映射）
以「标注前备份.docx」的 media 为基准，用 `scripts/replace_media.py` 按 md5 只换 ZIP 内
对应 media 字节，其余 part 原样保留；宽高比变了要同步改 `wp:extent` 与 `a:ext`。

## 5. 校验与收尾

- `verify_delivery.py --docx 设计原理.docx --shots 标注版目录`：图片映射齐全、
  文档属性为空；正文敏感词零命中（admin/123456/URL/IP）。
- 章节标题序列前后一致、表格数不变、图注全部落在第二章区间内。
- `Kwps.Application` 转 PDF → PyMuPDF 渲染目检：截图完整、未裁切断页、标注清晰可读。
- WPS 转 PDF 会写回作者 `admin`，**之后**再跑一次 `strip_metadata.py`。
- 交付时提醒用户关闭 WPS 后重新打开，避免旧窗口保存覆盖已替换的图片。

## 6. 常见错误

- 单独出操作说明书 Word 而不嵌入设计原理第二章 → 用户退回（本次踩坑）。
- 截图无箭头标注 / 只打码 → 不像操作说明，退回。
- 截图塞入与主题无关的页面（统计/权限/仿真）→ 「截图不紧扣主题」，退回。
- 只写功能介绍不写点击步骤 → 「操作介绍不连贯、不全面」。
- 功能模块数少于申请表主要功能 → 「与申请表功能不符」。
- 正文写出真实账号密码 / 服务端 IP → 泄密且不专业。
- 标注顺序颠倒（先标注后打码）→ 标注被马赛克糊掉。
